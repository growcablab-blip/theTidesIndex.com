# OWNER DECISIONS

Decisions that are the owner's to make. Each records what was done in the
meantime, so nothing was blocked waiting for an answer. Overruling any of these
is expected to be cheap.

---

## 1. SRC-011 attribution conflict — needs a human to open the file

`SOURCE_MANIFEST.json` records SRC-011 as *Peptide Characterization and
Application Protocols*, ed. **Gregg B. Fields**, Humana Press, 2007. The
filename of the held copy names **Colin T. Mant**, who is associated with *HPLC
of Peptides and Proteins*. These are different works.

This matters more than a metadata slip: SRC-011 is a `core` priority source for
the analytical chemistry that the entire quality section rests on. Citing a
misidentified source would corrupt provenance for exactly the material the
platform most needs to get right.

**Done in the meantime:** QC status moved from `incomplete` to `pending`, so the
source is not citable and the publish gates will refuse it as provenance. Logged
as verification issue V-013 at critical priority.

**Needed:** open the copy, confirm title page, editor, publisher and year.
Then either correct the registry or replace the file.

## 3. One workflow status on evidence records

`CONTENT_SCHEMA.md` specifies both `verification_status` and
`publication_status` on claims and protocols. Two independently-writable status
columns can disagree — `publication_status='published'` alongside
`verification_status='rejected'` — which is an unacceptable state for a
provenance system.

**Done:** a single `workflow_status` ladder on evidence records; public
visibility derived from it. `publication_status` retained on `publications`,
where a document lifecycle genuinely is an independent dimension.

## 4. What `patient_visibility` means on a protocol

Read as: *this protocol record may be referenced in patient-facing context at
all* — never as *dose tables render for patients*.

**Done:** patient mode reads `public_v_protocol_simple`, which has no dosing
columns and no free-text clinical fields, regardless of this flag. A patient
sees that named sources describe regimens, what those regimens were aiming at,
in whom, and by which route. Nothing that functions as an instruction.

**Confirm** if you meant something stronger — for example that protocols should
not surface in patient mode at all, even as an attributed existence statement.

## 5. Supabase project

No credentials, so no hosted database is provisioned. Everything runs against
local Postgres and, in tests, an in-process one.

**Needed when you want it wired:** a Supabase project URL, anon key and service
role key, plus the database connection string. Migrations apply with
`npm run db:migrate`.

A second, restricted database role for the public read path is worth creating at
the same time: it would hold privileges only on the `public_v_*` views, so the
public side of the application cannot read a draft record even if a query asks
for one. `src/server/db/client.ts` already splits the two connections and falls
back to one until that role exists.

## 6. Analytics and telemetry

`ACCEPTANCE_TESTS.md` H requires a documented decision.

**Proposed default:** no third-party analytics at launch. If measurement is
wanted, a cookie-less, self-hosted or privacy-preserving option only — a
clinical reference that a physician is comfortable sending to a patient should
not be carrying advertising-adjacent tracking.

**Needed:** confirm, or name a preferred tool.

---

## 7. Seed compounds that are not peptides

The master index includes MK-677 (ibutamoren) and 5-Amino-1MQ, which are small
molecules, not peptides. Neither is in the first cohort, so nothing is blocked.

**Done:** `compound_types.is_peptide` exists so the interface can state this
plainly when those records are created.

**Worth deciding before they are built:** whether The Tides Index indexes
non-peptide compounds at all. There is a reasonable case either way — they
appear in the same clinical conversations, but including them widens the scope
the name implies.
